# C. 指令层 Checklist

指令层审查 SKILL 的工作流是否能被 Agent 无歧义地执行。

---

## C1: 工作流步骤有明确顺序

**检查位置**：SKILL.md 中的工作流或步骤描述
**通过条件**：步骤有明确编号或顺序标记（Step 1/2/3 或 Phase 1/2/3）；顺序不依赖 Agent 自行判断
**不通过 → Major**
**改进建议**：将工作流重写为有编号的步骤序列，每步聚焦一个具体动作

---

## C2: 关键步骤有 Gate 条件

**检查位置**：步骤之间的转折处，尤其是"需要用户输入后才能继续"和"前置条件未满足时应终止"的节点
**通过条件**：在上述关键节点有显式 Gate 声明，如 "DO NOT proceed to Step N until..." 或 "If X is missing, stop and report"
**不通过 → Critical**（无任何 Gate），**Major**（关键节点缺少 Gate）
**改进建议**：在每个依赖前一步结果的节点前添加 Gate 条件；Gate 应包含：触发条件 + 未满足时的处理方式

---

## C3: 指令使用祈使句

**检查位置**：所有步骤描述
**通过条件**：步骤动作使用清晰的祈使句（"Read X"、"Check if Y"、"Output Z"），而非"你可以"、"建议"、"可能需要"等软性措辞
**不通过 → Major**
**改进建议**：将"可以考虑读取"改为"Read"；将"可能需要"改为条件句 "If X, then do Y"

---

## C4: 无缺乏判断标准的模糊词

**检查位置**：全文（包括 references/）
**通过条件**：不存在没有判断标准的模糊词，如"适当"、"合理"、"酌情"、"如有必要"，或这类词后面跟有明确的判断标准
**不通过 → Major**
**改进建议**：将模糊词替换为可判断的条件，如将"适当增加间距"改为"间距不足 8px 时增加到 8px"

---

## C5: 规则无矛盾

**检查位置**：全文（包括 references/ 中的所有 checklist 或规则文件）
**通过条件**：未发现两条规则在相同条件下要求不同行为
**不通过 → Critical**
**改进建议**：明确优先级（"当 X 和 Y 冲突时，优先遵循 X"），或删除其中一条矛盾规则

---

## C6: 无显著冗余

**检查位置**：全文
**通过条件**：同一条规则未在多处原文重复（允许少量跨文件引用，但不应逐字复制）
**不通过 → Minor**
**改进建议**：合并重复内容到一处，其他位置改为路径引用

---

## C7: 条件分支覆盖主要异常场景

**检查位置**：工作流中的判断节点
**通过条件**：每个 "If X" 都有对应的处理路径；不存在只处理 happy path 而完全忽略异常情况的判断节点
**不通过 → Major**
**改进建议**：为每个判断节点补充 "else" 或 "if X is missing/fails" 的处理路径

---

## C8: 不假设 Agent 有跨会话记忆

**检查位置**：全文
**通过条件**：SKILL 不要求 Agent 依赖上次会话内容，或提供了明确的持久化机制（如"结果写入文件 X，下次使用时读取"）
**不通过 → Major**
**改进建议**：将需要跨会话保留的上下文写入文件，在步骤中明确 "read the previously saved file at [path]"
