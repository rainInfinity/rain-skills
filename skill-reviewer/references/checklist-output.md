# E. 输出层 Checklist

输出层审查 SKILL 的输出是否可预期、有结构、可被下游使用。

---

## E1: 输出有明确格式规范

**检查位置**：SKILL.md 或 assets/ 中的输出说明
**通过条件**：SKILL 明确说明输出的格式（如 Markdown 报告、JSON、代码文件）及其结构（包含哪些部分）
**不通过 → Critical**（完全无输出格式说明），**Major**（有说明但过于模糊，如仅写"输出报告"）
**改进建议**：在 SKILL.md 中添加输出格式章节，或将完整模板放入 assets/

---

## E2: 输出有具体示例或可填写的模板

**检查位置**：SKILL.md 或 assets/
**通过条件**：提供至少一个输出示例，或 assets/ 中有可供 Agent 填写的模板文件
**不通过 → Major**
**改进建议**：添加示例输出（最小化示例即可）；或在 assets/ 中创建带占位符的模板文件

---

## E3: 需跨会话复用的输出有持久化策略

**检查位置**：工作流中产生中间结果或最终结果的步骤
**通过条件**：如果输出需要在后续会话中复用，有明确的文件写入策略（写到哪个路径、什么格式）；单次会话单步输出此项为 N/A
**不通过 → Major**
**改进建议**：指定输出文件路径和格式，如 "save to design-system/MASTER.md"；并在工作流中说明何时读取

---

## E4: 边缘情况的输出行为有说明

**检查位置**：全文
**通过条件**：说明了无输入/空结果/执行错误时的输出行为（输出什么内容或采取什么替代动作）
**不通过 → Minor**
**改进建议**：添加"当没有结果时输出 [X]；当发生错误时输出 [Y]"的说明

---

## E5: 模板结构固定，不依赖 Agent 自由发挥格式

**检查位置**：输出格式说明 + assets/ 中的模板
**通过条件**：相同类型的输入应产生结构一致的输出；模板中有明确的占位符，Agent 只填内容不改结构
**不通过 → Major**
**改进建议**：在指令中明确写 "fill in the template at assets/xxx.md, DO NOT change the structure"

---

## E6: 输出对下游有明确交接接口

**检查位置**：输出说明部分
**通过条件**：如果该 SKILL 的输出将被其他 SKILL 或工作流消费，说明了输出字段含义及使用方式；standalone SKILL 此项为 N/A
**不通过 → Minor**
**改进建议**：在输出说明中添加"输出字段含义"或"下游如何使用此输出"的说明
