# F. 可维护性层 Checklist

可维护性层审查 SKILL 能否在不同项目中复用，以及随时间演进的能力。

---

## F1: 无项目级硬编码假设

**检查位置**：全文（包括 references/ 和 assets/）
**通过条件**：不包含特定项目的名称、路径、人名、项目专有变量；或这些内容在一处集中声明为可配置项，其余部分引用变量
**不通过 → Critical**（大量分散硬编码，导致 SKILL 无法复用），**Major**（少量但出现在核心流程中）
**改进建议**：将项目特定配置提取到 SKILL.md 顶部的 Configuration 章节或单独配置文件，其余部分统一引用

---

## F2: 数据与指令逻辑分离

**检查位置**：SKILL.md 中是否有大量内联数据（规则列表、色值表、配置常量、CSV 内容等）
**通过条件**：可变数据（会随时间更新的规则/列表/配置）存在于 references/ 或 data/ 中；SKILL.md 中只有固定流程逻辑
**不通过 → Major**
**改进建议**：将数据移入 references/data/ 目录；SKILL.md 中通过文件路径引用，如 "read data/rules.csv"

---

## F3: 平台或框架专有规则有范围标注

**检查位置**：规则列表、checklist、Quick Reference 等
**通过条件**：针对特定平台（如 iOS、Android、Web）或框架（如 React Native、SwiftUI、Next.js）的规则有明确的适用范围标注
**不通过 → Major**
**改进建议**：在规则旁添加平台标注，如 `(iOS only)`、`(React Native)`、`(Web)`；通用规则无需标注

---

## F4: 适用范围在 Skip 条件中清晰界定

**检查位置**：When to Apply → Skip
**通过条件**：Skip 条件能清晰排除不适合该 SKILL 的项目类型或场景
**不通过 → Minor**
**改进建议**：在 Skip 中补充"不适用于 [具体项目类型或场景]"

---

## F5: 外部资源链接指向稳定地址

**检查位置**：全文中的 URL 链接
**通过条件**：链接指向稳定的官方文档（GitHub 仓库、官方 docs 站点），不是临时页面或个人博客；易变链接有注释说明
**不通过 → Minor**
**改进建议**：优先链接官方 GitHub/docs 站点；对易变链接添加注释"此链接可能需要更新"

---

## F6: 规则修改只需改一处

**检查位置**：整体结构
**通过条件**：修改某条规则时，只需修改 references/ 中的单一文件，不需要同时修改 SKILL.md 和多个其他文件
**不通过 → Minor**
**改进建议**：将同类规则集中到一个文件；避免同一规则的内容散落在 SKILL.md 和 references/ 的多个位置
